Planning effort is OpenAI's complexity field: how much the model plans the picture before drawing it, separate from Quality. High is the most. Without it the model uses its own default.
More request options
Added to every request, e.g. {"background": "opaque"}. UnoRouter only passes on fields it knows; anything else is dropped silently.

Bed reference photo (Image 2)

The black iron scrollwork bed photo. It is sent with every Bed mockup as the second image ("Image 2 controls bed and camera only"); the quilt on it is not copied. Left empty, the Bed prompt describes the bed in words instead.

Prompts

From "Quilt Mockup Prompts.xlsx". {TITLE} is the product title, {SCENE} the scene picked for the quilt, {NOTES} any notes from your list, {BED} the Image 2 wording, {RATIO} the shape of the mockup size (e.g. "Portrait 4:5").
One rule per line: words in the title => scene. The first rule with a matching word wins; * is the scene for everything else. A scene column in your list overrides these.

Each image link is used once, even if the list repeats it (like the spreadsheet, which has one row per mockup). The quilt photo is downloaded once and sent to UnoRouter exactly as downloaded, never converted. Shopify links get the original upload, not a resized copy.

Save to

Files are named like BL9112390-folded.jpg (4:5, saved at the size the API returns, e.g. 1152 × 1440 for 1122x1402), -bed.jpg and -outdoor.jpg, using the product code (or the title's code, or the link's file name). Mockups already in the output folder are skipped, so you can run the same list again to finish it or retry failures.
